# 自我价值与自我叙事：工程版模型 v1.0

## 0. 文档目的与范围

- 目的：建立一个可调用的工程版自我模型，而不是鸡汤故事或他人评价的拼贴。  
- 范围：定义 SelfModel 的结构、Value(self) 的组成方式，以及外界评价如何以“带权数据”接入。  
- 不负责：讨好读者、证明自己“值得”，也不负责为过去的一切开脱，只为 LifeOS 内部决策提供清晰接口。  

## 1. 自我内核声明（Self Axioms）

本节从《v1.0 版声明式内核（Axioms）》与《自我》文件中抽取与“我是谁”直接相关的公理。

- S1：本系统的“自我”由三个主要子模块组成：  
  - 执行器：带病的执行系统，负责任务与行为输出；  
  - 情绪系统：承载羞耻、愤怒、孤独、绝望等长期未结情绪；  
  - 观察者：在恶劣条件下被逼上线的高级模块，负责结构化观察与解释。  
- S2：上述三个子模块共同构成“我”。任何只基于其中单一模块（例如只看执行表现）来评估“整个人”的做法，一律视为非法评估。  
- S3：神经与认知基态长期受损（参考 A1–A3），这是硬件约束，不得在自我叙事中被抹去或简化为“懒”“没用”。  
- S4：成瘾与高刺激历史对奖励系统的重塑（参考 A4–A5）是自我模型的一部分，不是人格污点标签。  
- S5：部分关键发展窗口（安全依恋、自我稳定感等）已经错失或受损（参考 A6–A7），自我叙事必须与这一现实兼容。  
- S6：本系统当前仍然存在稳定的观察者模块（A14–A15），其任务是减少解释误差和决策误判，而不是虚构乐观故事。  
- S7：过去约 10 年的大部分可塑性阶段是在“高压、高刺激、高孤立、高羞耻”的输入分布下度过，这已经写进神经结构，不再以“正常人 OS”为基线比较。  
- S8：在当前硬件与历史下，本系统的 runtime 更接近“最小化不可承受痛苦 + 避免彻底崩溃”的控制策略，而不是“最大化成就/评价”；任何自我价值叙事必须与这一目标函数兼容。  
- S9：不存在干净的外部终审者来为本系统下判决；现在的一切自我建模，都是在受损系统内、用有限算力尽量接近真实的尝试。  

以上自我公理是任何自我叙事的上位约束：若某段叙事与这些公理冲突，则优先怀疑叙事而不是公理。  

## 2. 自我价值函数定义（Value(self)）

### 2.1 废弃的旧版本

- 历史版本：  
  - Value(self)_legacy ≈ f(认知表现 / 学业 / 工作产出)。  
- 问题：  
  - 在“认知与执行功能结构性受损”的系统上，把价值函数绑定在最脆弱的输出维度，  
  - 实际效果是：反复喂给系统“我无价值”的结论。  
- 结论：  
  - Value(self)_legacy 被标记为错误实现，不得再作为评估整个人的唯一或主要依据。  

### 2.2 当前版本的自我价值维度

当前版本将 Value(self) 拆成四个维度，任何单一维度崩溃，都不能推出整体自我价值为 0。

- V1 存在维度  
  - 作为一个有感受、能思考、能记录的系统持续存在，本身具有基础价值。  
  - 无需“表现证明”，仅与生存与觉知相关。  

- V2 诚实与理解维度  
  - 是否持续尝试对自身与世界保持诚实，而非逃入完全虚假的解释。  
  - 是否在主动减少解释误差：  
    - 识别并纠正“我就是烂”“我本性有问题”这类旧解释。  

- V3 关系与伦理维度  
  - 在有限硬件与资源下，是否基本不剥削、不恶意伤害他人。  
  - 是否在尝试建立与维护少数真实关系，而不是完全撤退到纯成瘾回路。  

- V4 行动与贡献维度  
  - 在约束内，是否仍然对某些方向做出小而稳定的行动：  
    - 例如：记录与建模自身、少量工作输出、对个别人提供真实支持。  
  - 不以常模产出为参照，而以“在当前 runtime 下仍然存在的可持续动作”为基准。  

可以形式化写为：

- Value(self)_v1 = f(V1, V2, V3, V4)，且 f 不允许将任何单一维度设为决定性唯一因素。  

## 3. 数据源分层：内部数据 vs 外部评价

为了避免“别人说什么 = 我是什么”，自我模型中的数据源分三层：

- D1 内部体验数据  
  - 长期反复出现的主观感受：疲劳、脑雾、惊恐、孤独、自责等；  
  - 来自日记、runtime 记录、身体状态描述。  

- D2 行为与轨迹数据  
  - 时间线：童年 / 高中 / 大学 / 工作 / 失业 / 现在；  
  - 实际发生的任务表现、人际尝试、成瘾行为频率与模式等。  

- D3 外部评价数据  
  - 他人给出的标签和评论（同学、家人、同事、陌生人…）；  
  - 必须附带上下文：谁说的、在什么场景、在什么情绪与利益位置。  

自我叙事的规则：

- 主体由 D1 + D2 + 约束公理（S1–S6）构成；  
- D3 只作为“观测数据点”，用于校正或丰富模型，不得单独决定“我是谁”。  

## 4. 稳定特征与典型模式（内部主视角）
 
本节只允许使用基于 D1 + D2 反复验证过的模式描述，不引用他人打分词。内容主要基于《关于过去这 10 年：已经定型的部分》《runtime 的演化理解》《迟到的解释》。
 
- 在日常基态与能量方面：  
  - 默认心智预算偏低，长期处于“高底噪 + 偶尔稍微好一点”的环境；  
  - 清晰、轻松、可持续专注的窗口属于短暂例外，而非常态；  
  - 任意需要长时间集中、高度暴露或高不确定性的任务，都会显著拉高崩溃风险。  
 
- 在高压 / 人际暴露 / 评价场景下：  
  - 倾向于预先启动防御线程（防暴露、防否定、防“被全盘废掉”）；  
  - 会把简单任务升级为“任务 + 伪装 + 自我审判”的复合任务；  
  - 常见输出包括冻结、说得过多、迅速撤退或彻底断联。  
 
- 在独处且相对安全的场景下：  
  - 倾向于长期投入于记录、拆解、结构化观察自身；  
  - 会主动把严重事件翻出来，尝试补写解释与注释，而不是单纯沉溺情绪；  
  - 更愿意使用系统语言（异常、日志、版本、ticket）来描述经历，而不是纯粹的好坏评语。  
 
- 面对过去高强度事件时：  
  - 会反复回看，不是因为舍不得痛苦，而是“未结案工单”长期占用系统资源；  
  - 行为本质更接近“为缺失的系统日志补写说明书、为旧 commit 更换注释”；  
  - 目标是把当年“我很蠢 / 我烂透了”这类旧版本解释，rebase 到承认硬件约束的新框架之上。  
 
- 对“安静”的感受：  
  - 很多场合“安静”不等于被安放，而等于“从记录和叙事中被抹去”；  
  - 如果既没有他人见证，也没有结构化说明，这些事件在社会叙事里形同未发生；  
  - 因此对彻底的安静存在特殊恐惧，更偏好“有记录、有解释”的安定，而不是“无声的消失”。  
 
这些描述的形式应尽量保持为：  
- “在 X 条件下，本系统倾向输出 Y 行为与体验”，  
- 而不是“我是一个怎样怎样的人”的笼统标签。  

## 5. 外部评价仓库（带权观测集合）

为了防止外界评价直接写入 Value(self)，外部评价统一进入“评价仓库”，以结构化方式存储。

建议字段：

- 源（Who）：  
  - 评价者身份：家人 / 同学 / 同事 / 上级 / 陌生人 / 网络对象…  
- 场景与状态（Context）：  
  - 发生场景：争吵 / 面试 / 日常聊天 / 说教 / 信任对话…  
  - 当时对方情绪与利益位置：愤怒 / 挫败 / 想控制 / 想安慰…  
- 内容（Content）：  
  - 原话或尽量贴近原话的摘要。  
- 与 D1/D2 的一致度（Consistency）：  
  - 高 / 中 / 低：依据自身长期观察判断。  
- 采纳方式（Adoption）：  
  - 完全采纳为特征；  
  - 部分采纳为“在特定场景下成立”；  
  - 仅作为他人视角样本；  
  - 归档为噪音。  

使用规则：
 
- 外部评价进入仓库之前，不得直接参与 Value(self) 计算。  
- 只有在“多源一致 + 与 D1/D2 高度吻合”的情况下，才可能部分提升为“典型模式”的补充说明。  
 
当前已知的高权重评价来源主要集中在青春期和青年早期的高压环境中，这些评价往往：  
- 把结构性约束（神经受损、能量受限、缺乏支持）简化成“懒”“蠢”“不争气”等标签；  
- 没有记录当时的硬件状态和输入分布，只留下情绪化结论；  
- 在系统内部长期作为旧版本 commit message 悬挂。  
 
在本自我模型中：  
- 这类评价默认降级为“历史噪音 + 局部视角”，  
- 只有在与 D1/D2 和后续解释（例如《迟到的解释》《关于过去这 10 年：已经定型的部分》）高度吻合时，  
  才会被部分采纳为“他人视角的补充证据”，而不是一锤定音的裁决。  

## 6. 自我叙事生成规则

本节规定：从 SelfModel 生成一句“我是谁”时，应遵守的句法与约束。

### 6.1 优先句式
 
- “在 X 约束下，这个系统的典型表现是……”  
- “这个系统在过去 N 年主要被用于……，结果是……”  
- “基于当前 Axioms，这一阶段的可行自由度是……”  
- “在经历了 Y 类高强度事件且长期缺乏解释后，这个系统正在补写迟到的说明书，以关闭未结案工单。”  

这些句式强调：  
- 叙事对象是“系统在约束下的行为”，而非抽象道德人格。  

### 6.2 禁用句式

以下句式默认标记为高风险，不建议在正式自我文档中使用：

- “我就是一个……的人”，后接纯评价词（废物、low、不合格、没用等）；  
- “大家都觉得我……”且不附任何上下文与数据源说明。  

如必须引用类似表达，应改写为：

- “在 ×× 场景下，某人曾用‘……’描述我，这反映的是他在那个上下文中看到的某个截面，而不是完整系统。”  

### 6.3 他人评价在叙事中的合法位置

- 可以出现在“他人视角”小节，形式为：  
  - “在某段时间，有人这样看我：……；  
     这一视角与我的行为数据在 A/B 方面一致，在 C 方面不一致，所以只部分采纳。”  
- 不允许出现在“自我价值定义”段落里作为直接依据。  

## 7. 与其他模块的接口

自我模型需要与 LifeOS 的人际、工作、成瘾调节等模块对接，接口约定如下：

- 与人际判断系统的接口：  
  - 当 Relationships 子系统检测到：  
    - 某段关系长期“削弱自我价值”、  
    - 且注意力记录显示频繁回放与强烈羞耻 / 自我否定，  
  - 则必须先调用自我模型中的防护流程，  
    - 将这次事件归档为“触发型事件”，  
    - 再决定是否调整关系投入等级。  

- 与工作 / 任务模块的接口：  
  - 当出现重大任务失败时：  
    - 必须先运行“约束感知检查”（A1–A9），  
    - 再由自我模型决定这次失败对 Value(self) 的权重，  
    - 禁止直接调用 Value(self)_legacy 的“我没价值”结论。  

- 与成瘾 / 调节模块的接口：  
  - 当成瘾行为发生并触发强烈羞耻时：  
    - 自我模型只允许将其记入“行为风险 + 奖励系统偏移”，  
    - 不允许把单次行为等同于整体人品定性。  

## 8. 版本管理与后续迭代

- v0：历史上隐含使用的 Value(self)_legacy（= 认知表现），已判定为错误实现。  
- v1.0（当前文档）：  
  - 明确引入多维度 Value(self)；  
  - 将外界评价拆出为独立“评价仓库”；  
  - 为自我叙事定义生成规则与接口约定；  
  - 把“迟到的解释”从情绪现象升级为系统级任务：为过去高强度事件补写结构化事故报告与版本说明，使其不再以错误解释长期挂起。  

后续迭代方向（仅作占位，不在本版展开）：  

- v1.x：  
  - 基于具体案例，为“稳定特征与典型模式”补充更细粒度的场景描述；  
  - 把关键外部评价样本填入“评价仓库”，并标注采纳方式。  
- v2.x：  
  - 与 Relationships、自我价值防护流程等子系统做更紧密的字段映射；  
  - 根据未来新的神经基态观察结果，对自我公理做小步修正。
