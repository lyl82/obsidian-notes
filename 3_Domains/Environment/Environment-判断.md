# LifeOS · Environment 环境对象 · 判断卷

本卷给出「Environment 环境对象」的判断框架，用于在具体日常中快速回答三个问题：

- 现在的环境状态，属于哪个等级？（可用 / 警戒 / 失效）
- 在当前日型与能量状态下，我至少需要做到什么？（最低动作集）
- 哪些情况被视为系统故障，必须被记录并用于修订规则？（事故）

判断卷不讨论审美，只关心环境是否足以支撑 LifeOS 的稳定运行。

## 一、状态等级：可用 / 警戒 / 失效

### 1.1 可用状态（OK）

满足以下大部分条件时，Environment 视为处于「可用」状态：

- 任意时刻 5 分钟内可以获得：
  - 饮用水（一杯常温水即可，不要求理想温度）。
  - 一份可直接吃或稍加处理即可吃的食物。
  - 一块可以直接躺下睡觉的空间（床或替代方案）。
- 房间内存在清晰的行走路径，不需要跨越大量杂物才能到达门口、床、桌面等关键节点。
- 桌面上有一块可供电脑 + 鼠标 + 一杯水的空白区域，可以在 1 分钟内进入工作或记录状态。
- 没有明显威胁健康或睡眠的环境问题（严重异味、明显霉变食物暴露、地面严重湿滑等）。

### 1.2 警戒状态（Warning）

出现以下任一情况，即视为进入「警戒」状态：

- 水 / 食物 / 可睡眠空间三项中，有一项需要 ≥5 分钟以上的准备才能获得。
- 床上杂物过多，需要明显整理才能躺下（但通过 10–20 分钟的整理可以恢复）。
- 桌面基本被占满，只能通过临时堆叠或移动大量物品才能开始工作。
- 垃圾袋已满、明显堆积，开始溢出生活区，但仍然可以在单次行动内打包带走。
- 一次性的混乱事件（如大件快递、拆包等）尚未被消化，但主要通路仍然畅通。

### 1.3 失效状态（Failure）

出现以下任一情况，即视为 Environment 已经「失效」，需要被记录为事故：

- 无法在 5 分钟内获得可喝的水或可吃的东西，且当下没有简单替代方案（如外卖 / 便利店）。
- 床面被占据到，在 10 分钟内无法恢复到可睡状态，导致需要熬夜整理或被迫在地上/椅子上睡觉。
- 房间主要通道堵塞，夜间起身存在明显绊倒或受伤风险。
- 垃圾、过期食物或污渍堆积到，明显影响呼吸、睡眠或情绪稳定（恶臭、虫害风险等）。
- 因为找不到关键物品（证件、钥匙、药物等），导致严重的现实后果（错过重要约定、无法就医等）。

一旦进入「失效」状态，不仅需要紧急处理，还必须在 DAO 中记录事件：时间、情景、直接后果和主观感受，用于未来修订定义卷与控制规则。

## 二、日型与最低动作集

Environment 的判断必须与日型结合：正常日 / 低能量日 / 崩溃日。

### 2.1 正常日

- 目标：在不压缩睡眠与能量恢复的前提下，将 Environment 维持在「可用」状态，并定期把「警戒区」消化掉。
- 最低动作集：
  - 睡前收尾窗口内，完成：
    - 床面恢复到可睡状态。
    - 房间内有可直接饮用的水源。
    - 急救食物库存检查并在可行时补足。
    - 明显溢出的垃圾打包并移出生活核心区。

### 2.2 低能量日

- 目标：接受输出能力下降的现实，允许部分环境进入「轻度警戒」，但保护「生命支持底线」。
- 最低动作集：
  - 即使当日不整理桌面、不做大扫除，也要确保：
    - 今晚有地方可以安稳睡觉。
    - 明早醒来时，房间内有可喝的水，与至少一种可吃的东西。
    - 不存在明显的安全风险（湿滑地面、大段裸露电线、尖锐物品散落）。

### 2.3 崩溃日

- 目标：不追求改善，只保证「不进一步恶化」与「保命」。
- 最低动作集（若身体与情绪允许）：
  - 床：清出一块能躺下的区域，哪怕其他地方仍然混乱。
  - 水：确保身边有一份可直接饮用的水（自倒、外卖、他人帮助皆可）。
  - 食物：确保存在一种能量来源（面包、零食、外卖），不苛求健康，只防止完全断供。
- 若连上述动作都无法完成，应视为 Health / SystemState 的问题优先级高于 Environment，暂停对环境的苛责，将注意力转向求助、医疗或睡眠。

## 三、触发条件与行动优先级

### 3.1 何时必须立刻行动？

在下列任一情形出现时，Environment 的维护优先级上升为「立即」：

- 距离睡眠时间不足 1 小时，而床仍然不可睡。
- 环境存在明显的安全隐患（火、电、水、尖锐物）可能在当夜或次日造成伤害。
- 已经连续两天以上没有可即用的饮用水或急救食物储备。

### 3.2 何时可以拖到夜间收尾窗口？

- 白天工作时注意到房间或桌面混乱，但：
  - 仍能维持可用状态。
  - 不影响当前任务的即时执行。
- 此时，只需：
  - 进行少量「顺手复位」动作（路过时捡起一个垃圾、带一个碗到水槽等）。
  - 把「房间/桌面整理」记入当晚的环境收尾清单。

### 3.3 何时可以完全忽略？

- 当天属于高压力或重大事件日（搬家、考试、加班到极晚），且环境仍处于「可用状态」。
- 在这种情形下，允许 Environment 完全让位于睡眠与恢复，后续在 DAO 中进行「一次性事件」标记，不将当日的混乱视为长期规则失效。

## 四、事故记录与规则修订

- 以下情形视为 Environment 领域的「事故」，必须在 DAO 中进行简要记录：
  - 因环境问题导致无法按计划入睡或严重延迟睡眠时间。
  - 因找不到关键物品而产生重大现实后果（爽约、迟到、无法完成重要任务）。
  - 因长期环境混乱而显著放大焦虑、抑郁或崩溃体验。
- 每当事故发生次数在一个时间窗口内（如一月内）超过可接受上限（例如 2–3 次），需要回看：
  - 是否定义卷中的「成功标准」过于理想化。
  - 是否判断卷中的阈值设置不合理（太宽松或太苛刻）。
  - 是否 Control 层（具体规则与流程）缺失，导致知道问题却没有可执行方案。
- 修订的方向不是「增加责备」，而是：
  - 降低不必要的复杂度。
  - 明确更小、更可靠的最低动作集。
  - 将环境维护进一步自动化、流程化，减少对当场意志力的依赖。
