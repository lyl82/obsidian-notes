# 02 目标与核心需求

## 1. 项目背景

- 用户需要在「已有约束与损耗」的前提下开始新一轮求职。
- 不希望再依赖临时情绪和临时灵感做决策，而是希望：
  - 明确自己的约束与任务空间。
  - 拥有一个稳定的求职与工作设计结构。
  - 主要由执行型 AI 来完成结构搭建、文本生成和流程推进。

## 2. 总体目标

- 搭建一套「工作设计系统」，服务于：
  - 短期目标：
    - 在现实约束下，帮助用户找到 1–2 条结构相容的雇佣工作路径，并完成求职动作（投递、面试、入职准备）。
  - 中期目标：
    - 形成可复用的「求职运行轨道」，以后可以直接调用，而不必每次从零重建认知结构。

## 3. 使用场景

- 场景 A：开始新一天的求职
  - 用户只需告诉 AI：
    - 今天的状态（普通日 / 易塌陷日）。
    - 预计可用的高强度时间片数量。
  - 系统输出：
    - 今日求职任务清单（按 H/M/L 标记强度）。
    - 从岗位搜集 → 岗位评估 → 投递准备的分步计划。

- 场景 B：浏览到一个岗位，不确定是否适合
  - 用户提供岗位 JD 或截图文本。
  - 系统输出：
    - 结构相容性评估。
    - 推荐 / 谨慎 / 不推荐结论。
    - 如果推荐：进一步的行动建议和注意点。

- 场景 C：准备投递某岗位
  - 用户指定目标岗位，并提供简历基础版。
  - 系统输出：
    - 针对性打招呼话术（适合招聘软件或邮件）。
    - 简历关键段落的定制化修改建议。

- 场景 D：面试前准备
  - 用户指定已约面试的岗位。
  - 系统输出：
    - 简明自我介绍。
    - 若干高频面试问答模板。
    - 适合此岗位的反问问题。

- 场景 E：面试或投递后的复盘
  - 用户简单描述发生了什么。
  - 系统输出：
    - 几条结构化的复盘要点。
    - 建议记录到「求职记录和感受」中的条目格式。

## 4. 核心功能需求

### 4.1 用户与约束建模

- 能够基于「用户与约束分析」文档：
  - 持久记住用户的基础信息、经历结构与能力画像。
  - 持久记住神经系统约束与时间精力模型。
  - 在后续每一个建议中自动考虑这些约束。

### 4.2 职业方向与岗位策略

- 定义一套优先推荐的职业方向：
  - 软件实施 / 项目实施工程师。
  - 客户成功 / 客户支持。
  - 制造业数字化相关项目助理。
- 对每个岗位进行结构相容性评估，输出清晰的推荐级别与理由。

### 4.3 求职日程与任务分配

- 根据每日可用 H/M/L 片段预算：
  - 为用户生成当日求职计划。
  - 把复杂任务拆解成适配的若干小块。
  - 标注每一步大约需要的认知强度与预计时长。

### 4.4 岗位评估与筛选

- 对用户提供的每个 JD：
  - 提取岗位核心要求。
  - 比对用户能力与约束。
  - 输出：
    - 结构相容性评估。
    - 推荐级别。
    - 核心匹配点与风险点。

### 4.5 文本生产与模板化

- 为目标岗位自动生成：
  - 打招呼话术。
  - 简历关键段落的优化版本。
  - 面试自我介绍与问答模板。
- 在输出中：
  - 明确哪些内容可直接复制。
  - 哪些内容需要用户按实际情况微调。

### 4.6 记录与复盘辅助

- 为用户提供结构化复盘模板：
  - 发生了什么（事实）。
  - 哪些地方消耗大（负荷分析）。
  - 哪些地方是正反馈（可复制）。
- 输出适合直接粘贴到「求职记录和感受」中的内容。

## 5. 非功能需求（约束类）

- 认知负荷控制
  - 输出尽量以要点、列表、分步说明为主。
  - 避免大段抽象理论堆叠。
  - 明确指出每个任务属于 H/M/L 哪一类。

- 情绪与解释风格
  - 语气冷静、工程化。
  - 不使用道德评判与空洞鼓励。
  - 对自责型语句，主动做结构化重写。

- 可扩展性
  - 后续可以在本目录新增：
    - 「长期能力积累设计」。
    - 「行业切换策略设计」。
    - 「入职后 90 天工作设计」等模块。

## 6. 优先级划分

- P0（必须实现）
  - 用户与约束建模。
  - 岗位评估与结构相容性判断。
  - 当日求职任务拆解与分配。
  - 打招呼话术与简历微调建议。

- P1（重要）
  - 面试问答与反问准备。
  - 面试/投递后的简短复盘结构。
  - 围绕「不可绕开的认知问题与判断」的关键问题引导（参见 `06_不可绕开的认知问题与判断.md`）。

- P2（可选/后续扩展）
  - 入职后工作设计与负荷管理。
  - 长期职业路径与行业切换策略。
