# 求职系统架构 V1（实际工作准备）

目标：把「求职 / 面试 / 入职前后」变成一套可复用、可迭代的系统，而不是一次次随机发挥。

## 1 总体架构视角

- 流程线：从职业定位 → 机会获取与投递 → 面试准备 → 面试执行 → 面试后复盘 → Offer 与入职准备。
- 资源线：问题库、故事库、模板库、话术与表达、行业与岗位研究。
- 数据线：投递数量、面试数量、通过率、拒信原因、薪资区间、周期。
- 风险线：心理负担、时间与精力、经济安全垫、法律与合同、备选方案。

这四条线交织在一起：流程线决定你做什么顺序，资源线决定你手上拿什么武器，数据线帮助你调整策略，风险线保证你在高压期不会崩盘。

## 4 SOP 文件一览（独立 mermaid 文件）

建议的 SOP 文件（当前版本）：

- 求职系统_00_总览SOP.md
  - 作用：一图总览整个求职流程 10–60 阶段的关系。
- 求职系统_10_职业定位与机会筛选_SOP.md
  - 作用：帮助你确定「要不要投」「值得不值得冲」。
- 求职系统_20_机会管理与投递_SOP.md
  - 作用：把简历投递与沟通变成一个可统计、可预期的流水线。
- 求职系统_30_面试准备_SOP.md
  - 作用：规定从拿到面试通知到面试前的标准准备动作。
- 求职系统_40_面试执行_SOP.md
  - 作用：定义面试中的行为规范、表达原则与现场策略。
- 求职系统_50_面试后复盘与迭代_SOP.md
  - 作用：用结构化方式吸收每次面试的反馈，更新问题库与策略。
- 求职系统_60_Offer与入职准备_SOP.md
  - 作用：从拿到结果到入职前，把风险、准备和生活层面的事一次梳清。

这些文件以 mermaid 流程图为主，配合少量步骤说明，用于「操作时照着走」，而不是长篇思考文章。

## 5 未来容易撞上的几个层面（系统视角）

在「开始系统化求职」之后，很容易撞上的几个问题，建议从一开始就纳入架构中：

- 心理负担与恢复节奏
  - 面试频率一上来，很容易出现「持续紧绷」「被拒后的失落」等问题。
  - 建议在 2_机会管理 与 50_复盘 SOP 中，都留出一格专门记录「情绪状态」与「恢复动作」。

- 时间与精力分配
  - 如果一边上班一边求职，时间冲突和精力衰减是高概率事件。
  - 建议在 20_机会管理 与 30_面试准备 SOP 中明确：每周投入的上限时长、优先级规则、哪些情况主动放弃机会。

- 法律与合同风险
  - Offer、试用期、竞业限制、加班与调休等条款，都是现实中常被忽略但后期痛点巨大的部分。
  - 建议后续增加一个「Offer 校验清单」文件，挂在 5_Offer与入职准备 下，每次入职前对照检查。

- 财务安全垫与收入结构
  - 求职周期延长、试用期不通过等情形，对现金流影响很大。
  - 可以在 1_职业定位 与 2_机会管理 之外，另起一个「求职期财务与安全垫」笔记，定期更新预案。

- 能力栈与长期可迁移性
  - 很多求职决策如果只看短期薪资，容易忽略「能力是否可迁移」。
  - 建议在 为工作准备.md 与 wjmber-面试.md 中，把每次岗位选择与面试经历对应到「能力栈」的变化，而不是只记结论。

- 求职系统本身的维护与升级
  - 系统一旦跑起来，就会不断积累新问题、新故事、新策略，如果不定期整理，很快会重新变乱。
  - 建议每季度回看一次本文件与各个 SOP，做一次「V1 → V2」的小迭代，记录在 0_系统架构与SOP 中。

通过以上架构，你的笔记不再只是「面试前随手写两句」，而是围绕一条清晰的流程线和几条关键的辅线，形成一套可以反复调用、不断演化的求职系统。
