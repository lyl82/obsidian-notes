# 人生OS 时间流日志分析计划书（v1）

## 1. 背景与目标

- 输入：人生OS「时间实际表」导出的 CSV，字段包括：
  - 初时间、完成时间、持续时间（整数）
  - 标题、log描述、done描述、doing 描述
  - 对象-人（引用）、对象标签、行动描述、父记录 等
- 目标：在不依赖完美记录的前提下，给出一份**事实性、可量化**的时间使用概览，作为后续主观复盘的基础。
- 约束：
  - 仅使用数据中可以直接推导的事实（时间、标签、文字），不做价值判断。
  - 分类规则显式写出，方便后续调整。

## 2. 输入数据规范

### 2.1 必需字段

- 初时间：起始时间，字符串，格式假定为 `yyyy/MM/dd HH:mm`
- 完成时间：结束时间，字符串，同上
- 持续时间（整数）：以分钟为单位的时长（允许是小数或空）
- 标题：一句话标题，可为空
- log描述 / done描述 / doing 描述：更长的文字，可为空
- 对象标签：如「锻炼」「物理移动」等，可为空

### 2.2 容错原则

- 若「持续时间（整数）」缺失但起止时间存在，则用时间差计算。
- 若起止时间也缺失，则该记录仅用于计次，不计入总时长。
- 时间解析失败的记录，计入「异常记录」统计，单独列出。

## 3. 分析维度和核心指标

### 3.1 全局概览

- 覆盖日期范围：最早的「初时间」到最晚的「完成时间」
- 记录条目数：有效记录总数
- 总时长：所有记录的持续时间之和（分钟与小时）
- 每日平均记录时长：总时长 / 覆盖天数

### 3.2 按自然日

- 每天的：
  - 总记录时长
  - 记录条目数
- 可以附加：
  - 日均时长波动（最大值、最小值、中位数）

### 3.3 按「原始字段」聚合（不带主观分类）

这些是最基础的事实聚合，任何进一步分类都基于此：

- 按「标题」聚合：
  - 每个标题的总时长、次数
- 按「对象标签」聚合：
  - 每个对象标签的总时长、次数
- 按「对象-人（引用）」聚合（如果有）：
  - 每个对象人的总时长、次数

### 3.4 可调节的「行动类别」分类

在脚本中引入一套**可配置的分类规则**，将每条记录归为一个或多个「行动类别」。示例初版类别：

- 求职与面试
- 思考与学习（认知、结构搭建）
- 锻炼与身体活动
- 娱乐与体验
- 生活与物理移动（吃饭、路程等）
- 模糊 / 未定义

#### 3.4.1 分类规则来源

- 从以下字段中查找关键字：
  - 标题
  - log描述
  - done描述
  - 对象标签
- 例如：
  - 出现「投递简历」「简历」「面试」「自我介绍」「口头表达」，则归类为「求职与面试」
  - 出现「锻炼」「引体」「深蹲」「骑行」，则归类为「锻炼与身体活动」
  - 对象标签中包含「物理移动」，则归为「生活与物理移动」
- 若多类命中，采用以下策略之一（脚本中可配置）：
  - 只取优先级最高的类别（定义一条优先级列表）
  - 或允许多标签分类，统计时按多标签拆分或并记

#### 3.4.2 按类别的指标

- 每个类别的：
  - 总时长（分钟、小时）
  - 记录条数
  - 在总时长中的占比
- 按「日期 × 类别」形成矩阵，可观察每天各类别的时间分布。

### 3.5 记录质量与「模糊时间」

- 统计「描述非常少或为空」的记录：
  - 判定规则：标题为空，且 log/done/doing 描述均为空
  - 这些记录的总时长和条目数
- 这部分时间可视为「客观记录存在，但主观含义模糊」，是未来优化记录习惯的重点区域。

### 3.6 衍生指标（为未来复盘准备）

不直接做价值判断，只提供可用的结构：

- 「对外动作」 vs 「内部准备」：
  - 对外动作：投简历、面试本体、打印简历、约面试等
  - 内部准备：练习自我介绍、思考面试问题、选衣服等
- 「脑力主导」 vs 「身体主导」：
  - 脑力主导：发散思考、写文档、学习、面试问答练习
  - 身体主导：锻炼、骑行、长时间物理移动

上述这些在分类规则中以关键字方法显式定义，但在报告中只呈现数字，不解释好坏。

## 4. 分析流程（供脚本实现）

### 4.1 读取与预处理

1. 读取 CSV 文件，使用 UTF-8（如有 BOM 则去掉）。
2. 将每一行转为内部记录对象，字段包括：
   - start_time（初时间，datetime）
   - end_time（完成时间，datetime 或 None）
   - duration_minutes（浮点数，分钟）
   - title、log_text、done_text、doing_text
   - tag_person、tag_object、action_text、parent_id 等
3. 对 duration_minutes 的处理：
   - 若字段有值，尝试转换为浮点数
   - 若无值但有 start_time 和 end_time，则用时间差推算
   - 若都没有，则记为 0，并在「异常记录」里打标

### 4.2 衍生字段

为方便聚合，增加：

- date：取 start_time 的日期部分
- weekday：星期几（0–6）
- hour_of_day：start_time 的小时

### 4.3 原始聚合

- 按日期聚合：sum(duration_minutes)、count
- 按标题聚合：sum、count
- 按对象标签聚合：sum、count

### 4.4 分类聚合

1. 定义一套「类别 → 关键字列表」的配置结构：
   - 针对标题和描述（title/log/done/doing）
   - 针对对象标签
2. 为每条记录调用分类函数：
   - 返回主类别（以及可选的多类别列表）
3. 按类别聚合：
   - 类别 → 总时长、记录数、占比
4. 按「日期 × 类别」聚合：
   - (日期, 类别) → 总时长

### 4.5 记录质量分析

- 统计以下数量和时长：
  - 起止时间缺失
  - 持续时间为 0 但有描述
  - 标题和所有描述都为空
- 给出：
  - 这三类的条目数、合计时长
  - 在总时长中的占比

## 5. 输出结构

### 5.1 机器可用输出（结构化）

脚本建议输出一个 JSON 或可序列化结构，包含：

- summary：
  - total_minutes
  - total_hours
  - day_count
  - avg_minutes_per_day
- by_date：日期 → { minutes, count }
- by_title：标题 → { minutes, count }
- by_object_tag：对象标签 → { minutes, count }
- by_category：类别 → { minutes, count, ratio }
- by_date_and_category：(日期, 类别) → minutes
- quality：
  - missing_time_fields：{ count, minutes }
  - zero_duration_with_text：{ count, minutes }
  - empty_meaning_records：{ count, minutes }

### 5.2 人类可读输出（自然语言摘要）

在 JSON 之外，脚本可以同时打印一段自然语言摘要，例如：

- 覆盖时间、记录总时长、每天平均多少小时
- 用前 N 大类别的占比解释「时间主要花在哪里」
- 报告「模糊记录」占比，提示未来可以在哪些环节多写几个字
- 把「对外动作 vs 内部准备」「脑力 vs 身体」这些指标以数字列出，但不做解读

## 6. 复盘中的使用方式

- 第 1 步：用脚本跑出这份事实性报告，只看数字和分布。
- 第 2 步：选一个关注视角（例如「求职结果」「恢复与能量」「结构搭建」），从对应类别的数字切入做主观反思。
- 第 3 步：如果发现某类时间很难解释（例如大量「模糊记录」），优先调整的是**记录习惯**而不是行动本身。

## 7. 版本与可扩展性

- 本计划书为 v1：
  - 分类规则基于关键字匹配，可在脚本中以配置形式维护。
  - 未来可以引入更复杂的 NLP 分类，但保持「事实优先」的原则不变。
- 建议：
  - 每次调整分类体系或字段含义时，更新本计划书对应章节。
