# 07. 数据结构规范

## 7.1 通用对象 Schema (YAML Frontmatter)

所有 PKOS 中的 Markdown 对象文件，推荐包含以下 YAML 头：

```yaml
---
id: UUID 或 简短唯一标识 (e.g., sys-meta-001)
type: System | Domain | Project | Concept | Person | Issue
title: 对象显示名称
status: Active | Archived | Draft | Frozen
tags:
  - 标签1
  - 标签2
created: YYYY-MM-DD HH:mm
updated: YYYY-MM-DD HH:mm
aliases: [别名1, 别名2]
---
```

### 字段说明
- **type**：决定了该对象属于哪个层级，应用什么模板。
- **status**：决定了该对象是否出现在日常视图中。
- **aliases**：便于在写作时通过不同关键词链接到同一对象。

## 7.2 流日志 Schema (Stream Log)

对应飞书多维表格/Excel 的列结构：

| 字段名 | 类型 | 说明 | 示例 |
| :--- | :--- | :--- | :--- |
| **初时间** | DateTime | 记录开始时间 | 2026/01/16 10:00 |
| **log描述** | Text | 核心内容、意识流 | "觉得现在的标签系统太乱了..." |
| **审查描述** | Text | 后期复盘时的备注 | "已在 v2.0 中修复" |
| **持续时间** | Integer | 分钟数 | 25 |
| **特殊标签** | Multi-Select | 关键分类 | `系统迭代`, `能量`, `Health` |
| **行动描述** | Text | 关联的具体行动 | "修改 Schema 文档" |
| **地理位置** | Text | (可选) | "Home" |

## 7.3 总结件 Schema (Summary Artifact)

每次深度对话后生成的沉淀文件（参考 `对话对象-模板.md`）：

```markdown
# 对话对象：{Title} ({Date})

## 0. 元信息
- 关联对象：[[Object_A]], [[Object_B]]
- 核心问题：...

## 1. 摘要 (Abstract)
- 关键洞见...

## 2. 决策与行动 (Decisions & Actions)
- [ ] Action 1
- [ ] Action 2

## 3. 系统回馈 (Meta-Feedback)
- 对系统本身的修改建议...
```
