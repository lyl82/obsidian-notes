**0. 对话对象化记录**

- 名称：LifeOS 笔记自动同步到 GitHub 的备份方案
- 创建时间：2026-01-20 约 22:10
- 关键背景事实（精简）：
  - 我的 LifeOS 笔记库在本地路径：`d:\个人记录\obsidian-file\wjmber\LifeOS`，主要通过 Obsidian 编辑。
  - 我希望这个笔记库能“实时/定期”备份到 GitHub，也可作为正式“发版流程”，而是安全备份。
  - 当前设备是 Windows，适合用 Git + PowerShell + 任务计划程序做自动化。

---

**1. 对话主题与目标**

- 这次对话主要在解决：如何让 LifeOS 本地笔记库自动且规律地同步到 GitHub，同时区分“日常备份”和“正式发版”。
- 目标是：搭建一个简单、稳定、低干扰的自动备份机制，让我写笔记时不用手动记得 `git add/commit/push`。
- 顺带理清：本地 Git 仓库初始化、自动备份脚本、连接 GitHub、未来如何自动化。

---

**2. 关键结论与共识**

- 使用 Git + GitHub 完全可以作为 LifeOS 的“备份层”，不必和“发版”混为一谈。
- 将 `LifeOS` 目录初始化为 Git 仓库是合理且已经完成的一步。
- 自动备份由一个 PowerShell 脚本负责：有变动时自动 `add + commit + push`，无变动则安静退出。
- 第一次手动 `git push -u origin main` 后，后续脚本可以无感知地 `git push` 到 GitHub。
- 定时执行脚本（例如每小时）可以交给 Windows 任务计划程序，而不需要改动 Obsidian 本身。

---

**3. 关键决策与理由**

- 决策 1：选择“Git 仓库 + GitHub 私有仓库”作为备份方案，而不是网盘同步。
  - 理由：Git 对文本非常友好，有历史版本、差异可视化，对 LifeOS 这种大量 Markdown 的笔记特别适配；GitHub 私有仓库又有可靠的远程存储和访问控制。

- 决策 2：用一个 PowerShell 脚本自动 `add + commit + push`，而不是让我手动敲命令。
  - 理由：我希望备份尽量“无脑化、低认知负担”；脚本可以统一处理“有变更才提交”“无变更就退出”的逻辑，还能统一 commit message 格式。

- 决策 3：区分“备份 commit”和“正式版本”，不限制备份的频率。
  - 理由：备份只负责安全，不负责语义；将所有自动提交命名为 `auto backup + 时间戳`，可以和我以后真正的“里程碑版本”（手动写 message 或打 tag）清晰区分。

- 决策 4：使用 Windows 任务计划程序按小时调用脚本，而不是在 Obsidian 里搞插件。
  - 理由：任务计划程序是系统级工具，稳定且与应用无关；即使 Obsidian 没开，只要电脑开机，就能定期备份，整体更可靠。

---

**4. 行动项（1–2 个）**

- 行动项 1（我自己执行）：  
  在 GitHub 创建一个私有仓库（例如 `LifeOS`），然后在本机 `LifeOS` 目录里依次执行：
  ```powershell
  git remote add origin https://github.com/我的用户名/我的仓库名.git
  git branch -M main
  git push -u origin main
  ```
  让自动备份脚本后续可以直接 `git push`。

- 行动项 2（我自己执行）：  
  在 Windows 任务计划程序中创建任务，每隔 1 小时执行：
  ```text
  powershell -ExecutionPolicy Bypass -File "d:\个人记录\obsidian-file\wjmber\LifeOS\auto-backup.ps1"
  ```
  起始路径设置为 `d:\个人记录\obsidian-file\wjmber\LifeOS`，实现真正的定时自动备份。
