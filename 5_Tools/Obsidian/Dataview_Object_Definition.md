# 🧩 对象定义：Dataview 引擎

## 1. 核心定义 (Definition)

> **第一性原理：** Dataview 是一个基于 **索引 (Index)** 的实时查询引擎。它通过扫描 Markdown 文件的 **YAML 前置数据** 和 **行内属性 (Inline Fields)**，将非结构化的笔记内容转化为可计算、可过滤、可聚合的 **结构化数据库 (Virtual Database)**。

- **本质：** 笔记系统的“读取接口 (Read API)”。
    
- **角色：** 人生 OS 中的“自动化审计员”与“视图生成器”。
    

---

## 2. 版本探测与判断 (Version 0.1 Check)

在人生 OS 的早期迭代（0.1版本）中，由于数据量较小，判断 Dataview 是否“健康运行”及“配置达标”的准则如下：

### [0.1版] 准入检查表 (Validation)

- [ ] **索引完整性：** 是否所有 `FROM #对象` 的笔记都至少拥有一个自定义属性（如 `status`）？
    
- [ ] **语法闭环：** 能否在不查看官方文档的情况下，独立写出 `TABLE`、`FROM`、`WHERE` 三段式语句？
    
- [ ] **实时性：** 修改某篇笔记的属性后，汇总列表是否在 2 秒内发生了自动更新？
    

### 性能基准 (Benchmarking)

- **查询耗时：** $T < 500ms$ (对于 1000 篇以内的笔记)。
    
- **数据密度：** 每个“对象”笔记的属性字段应 $\ge 3$ 个。

## 3. 认知结构 (Structural Hierarchy)

### A. 数据输入层 (The Input)

定义数据进入系统的三种“姿态”：

1. **强结构 (YAML):** 位于文件头，用于静态、核心定义。
    
    - `type: software_tool`
        
    - `category: plugin`
        
2. **弱结构 (Inline):** 位于正文，用于动态、随手记录。
    
    - `掌握进度:: 40%`
        
3. **隐性数据 (Metadata):** 系统自动生成。
    
    - `file.day`: 关联日期。
        

### B. 逻辑处理层 (The Logic)

这是你与数据沟通的语法：

- **过滤 (Filter):** `WHERE` —— 决定哪些信息进入视野。
    
- **转换 (Transform):** `FLATTEN` —— 将一个列表拆分成多行。
    
- **聚合 (Aggregate):** `GROUP BY` —— 发现事物间的共性。
    

### C. 表现层 (The View)

- **表格 (TABLE):** 决策、对比、审计。
    
- **列表 (LIST):** 快速预览、导航。
    
- **任务 (TASK):** 待办驱动。
