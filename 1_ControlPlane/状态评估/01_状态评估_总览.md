# 人生OS 1.0 · SystemState: 状态评估总览

| 字段 | 内容描述 |
| :--- | :--- |
| **目的** | 为日常运行提供统一的“状态语言”，避免用情绪或自责当作系统状态，支持“可带伤运行的人生系统”而非“成功人生系统”。 |
| **适用范围** | 系统内所有主动运行的 Service（工作、学习、社交、运动、思考）以及评估这些 Service 之前的“今天适不适合做这件事”判断。 |
| **核心维度** | 仅描述结构，不描述情绪细节：基础状态（能量/身体）、认知可用度（能不能思考）、情绪稳定度（波动是否淹没认知）。 |
| **输出** | 对当前时间窗给出一个简短标签，用于上层决策：例如【可用】【受限】【降级】【仅维持】【不可交互】。 |

---

## 1. 设计原则

- 不追求精细诊断，只给“够用”的标签，服务于后续决策。
- 不试图从状态里“悟道理”，只判断：现在哪些类型的操作是允许的，哪些是禁用的。
- 状态评估本身不带惩罚，只作为调度输入；任何自责、评价型语言都不写入本层。
- 不把长期结构性问题塞进本层，本层只描述“此刻 / 此段时间的可用性”。
- 默认系统可能“带伤运行”，甚至在未来出现认知功能长时间卸载的情况，因此本层用语尽量面向“未来的继承者”和“当时无法思考的自己”，避免复杂隐喻和解释性叙事。

---

## 2. 输出等级草案

- 可用：基础状态尚可，认知可用，可以运行日常计划和轻量反思。
- 受限：基础状态一般或波动较大，只适合运行少量关键任务，不做复杂反思。
- 降级：能量明显不足或连续受干扰，只运行维持生活的最低必要任务，不做自我评价。
- 仅维持：认知功能基本不可用，只维持生活体征和最小安全感，不对外做承诺。
- 不可交互：进入纯粹自我维持状态，无法可靠感知、表达和思考，对外一律视为“暂停可用性”。

---

## 3. 文档拆分说明

- 本文件只给出状态评估的总则和输出等级，不定义细节规则。
- 各种典型状态和判定准则拆分到独立文件，方便单独修改：
  - 《02_状态层级_基础与认知》：描述“基础状态”和“认知可用度”的组合。
  - 《03_状态_自我维持态》：描述“只有感受、没有认知”的特殊状态及对外语义。
  - 后续如需扩展“早晨/下午/晚间异常”等，可增加新的状态评估子文件，而不修改本总览。
